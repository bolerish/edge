Wisp adds directional border lighting to elements you already own. Keep your markup, styling, and interactions.

Getting started

This is an unreleased React MVP. The packages are currently private. Build and link the workspace packages before trying these imports. React 19 and StyleX 0.19 are the current peer targets; the workspace validates React 19.3.1 and StyleX 0.19.1. 

import * as stylex from '@stylexjs/stylex';
import { useLight, useSurface, type Light } from '@wisp-lighting/react';
import '@wisp-lighting/react/style.css';

function App() {
  const light = useLight();
  return <Card light={light} />;
}

function Card({ light }: { light: Light }) {
  const surface = useSurface<HTMLElement>(light, {
    material: 'raised', theme: 'wisp',
  });
  return (
    <article ref={surface.ref}
      {...stylex.props(surface.style, styles.card)}>
      Your content
    </article>
  );
}

const styles = stylex.create({ card: { padding: 24, borderRadius: 16 } });

Apply the returned StyleX value first, then your styles. Your position, radius, colors, and layout take precedence. Import the compiled library CSS once. The library's source does not need to run through your StyleX compiler; your own StyleX styles still do.

The API

useLight(options?) → Light

Own one stable light and pass it to the surfaces that share it. No Provider is required. The component calling this hook owns the light's lifetime; borrowing surfaces do not keep it alive after that owner unmounts.

Option Default Behavior
mode auto auto, pointer, or static
radius 480 Positive finite reach in viewport CSS pixels
intensity 0.75 Finite number from 0 to 1

Changing options updates the existing light. Omitted options use defaults. Pointer frames do not update React state or context.

light.refresh()

Invalidate cached geometry and schedule a frame. Call after React has committed a known layout change. This also works while the pointer is stationary. 

useEffect(() => { light.refresh(); }, [light, expanded]);

useSurface(light, options?) → { ref, style }

Attach ref to one HTML element and compose style with stylex.props. The default material is raised. Material changes update the same registration. Removing or replacing the element unregisters it and restores the library-owned inline variables. A node cannot belong to two lights.

surface.style is a StyleX value, not a React inline-style object. Reserve the host's ::after for Wisp. Do not attach it directly to an input or another replaced element; register a wrapper you own.

Materials and the Wisp theme

The optional theme: 'wisp' supplies a restrained dark surface with two choices: 01 Raised and 03 Matte. Leave theme unset to keep your existing visual design.

  • raised catches a directional edge highlight.
  • recessed reverses the direction for inset surfaces such as input wrappers. It is an engine material, not a Wisp theme choice.
  • matte softens the directional response.
function Search({ light }: { light: Light }) {
  const surface = useSurface<HTMLLabelElement>(light, { material: 'recessed' });
  return (
    <label ref={surface.ref} {...stylex.props(surface.style, styles.field)}>
      Search <input name="query" />
    </label>
  );
}

You can customize --wisp-highlight and --wisp-border-width through your styles. The controller owns --wisp-angle and --wisp-strength; do not write those same properties through React or another animation system.

Input modes and accessibility

Auto respects reduced motion and starts with fixed lighting when the primary device lacks precise hover. Actual mouse or pen movement can enable tracking when reduced motion is off. Touch movement does not drive the light.

Pointer explicitly opts into tracking, including when reduced motion is enabled. Offer it as a conscious choice. Static uses the same fixed direction on every surface, regardless of distance.

Lighting is decorative. Preserve useful base borders, text contrast, keyboard focus states and labels. Decoration does not capture clicks, and forced-colors mode hides it. Wisp does not replace native input values, selection, focus, keyboard behavior, or React's DOM composition.

Geometry, rendering and limits

Wisp supports axis-aligned HTML surfaces and same-document portals sharing a light. The effect is a directional rectangle approximation, not physically accurate point lighting. Directional light fades near the exact center, where its direction is ambiguous.

Registration, captured nested scroll, viewport resize, observed size changes, font loading and resource loads invalidate geometry. ResizeObserver does not detect every position change. Call refresh() after sibling insertion, position-only movement, or a transform animation. Rotated/perspective surfaces and cross-document portals are outside the current support scope.

Module evaluation and rendering do not access the DOM. SSR and static markup work before client activation, with a decorative CSS fallback; hydration connects the light. Hooks and effects clean up registrations, observers, listeners and pending frames, including React StrictMode replay.

One light uses one pointer listener and at most one pending frame. Reads precede writes and unchanged CSS outputs are skipped. Surface selection still grows with registered elements. Gradients can incur style, paint and compositing costs. Functional tests and a 500-surface playground are not FPS, GPU-only, battery or speedup guarantees.

Solid and Svelte adapters are not implemented. The core is framework-independent, but future support is not a current compatibility claim.
